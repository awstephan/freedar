# Domain docs

This is a single-context project.

## Before exploring

- Read the root GLOSSARY.md.
- Read relevant decisions under docs/adr/.
- Read DESIGN.md for agreed product behavior and VALIDATION.md for
  technical evidence and unresolved assumptions.

If glossary or ADR files are absent, proceed silently. Create them
lazily when terms or consequential decisions are resolved.

## Vocabulary and decisions

Use glossary terms consistently in code, tests, issues, and discussion.
Keep implementation details out of the glossary.

If a proposal conflicts with an ADR, identify the conflict explicitly
rather than silently overriding the decision.
